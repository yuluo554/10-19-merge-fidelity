# 04 · 数据计划（合成 fixture 与 golden）

> 上游口径：`data/README.md`（§三 合成数据纪律、§四 数值口径）。本文只写**生成器设计、目录形态、真值纪律、验收**。
> 全部 fixture 为本地合成假仓库，命名白名单已在 `data/README.md` §三 定死。

## 一、为什么"数据先行"

本项目的判定全部由 git 对象复算，**没有外部语料**——数据资产就是**注入已知缺陷的合成仓库 + golden 期望**。
生成器必须先于 `fidelity`/`parity`/`ledger` 落地，否则"M2 的 10 个 fixture golden"无从谈起。

## 二、生成器设计（`tools/gen_fixtures.py`）

### 2.1 确定性纪律

| 可变输入 | 固定方式 |
|---|---|
| 作者/邮箱 | `GIT_AUTHOR_NAME` / `GIT_COMMITTER_NAME` = `Fixture Bot`，`@example.invalid` |
| 时间 | `GIT_AUTHOR_DATE` / `GIT_COMMITTER_DATE` = 脚本内写死的递增 UTC 时间 |
| 提交信息 | 写死常量 |
| 分支名 | `main` / `release/1.0` / `feature/synth-a` / `feature/synth-b` |
| 文件内容 | 写死模板 + 显式注入 |
| 仓库路径 | 生成到 `--out`；**仓库路径不参与任何 OID 计算**（git 对象不含路径） |
| 排序 | 生成顺序固定，不用 `set` 迭代、不用 `random`、不读系统时钟 |
| 默认分支 | `git init -b main` 显式指定 |

**可重建判据**：两台机器（不同路径、不同时区、不同 `core.autocrlf`）重建后 `git rev-parse HEAD` 与全部 tree/blob OID 一致；`--check` 重生成到临时目录与冻结目录逐字节比对（`expect.json` 与仓库 OID 清单双查）。

### 2.2 CLI

```
py -3.8 tools/gen_fixtures.py --out data/fixtures [--only fidelity|parity|ledger|NAME]
py -3.8 tools/gen_fixtures.py --check        # 重生成到临时目录 → 与 data/fixtures 比对
```

- `--check` 退出码：0 = 一致；1 = 有差异（逐条打印文件/OID）；2 = 用法错误。
- 生成器自己**不依赖** `mergefidelity` 包（真值独立于被测实现）。
- 生成器在无 git 环境下 fail-fast（退出码 3），不产半成品。

### 2.3 `.gitattributes` 与 EOL

`data/fixtures/**` 下的合成仓库含 `.git` 目录，**不入仓**（生成物）。入仓的是：
- `tools/gen_fixtures.py`（生成器）
- `data/fixtures/<suite>/<name>/expect.json`（golden）
- `data/fixtures/<suite>/<name>/README.md`（一句话缺陷说明 + 手工复现命令）
- `data/fixtures/manifest.json`（suite/name/注入缺陷类型/期望计数/生成器版本）

`.gitattributes`：`data/fixtures/**/expect.json text eol=lf`（golden 必须 LF，逐字节比较的前提）。
合成仓库的 `.git` 目录由 `.gitignore` 排除：`data/fixtures/**/.git/`。

## 三、fidelity fixture 集（10 个）

**分类方向（M1 定稿，口径见 `data/README.md` §4.3）**：只用一个方向
`git diff -U0 <mechanical_tree> <recorded_tree>`，按 hunk 自身形态分：
含冲突标记 → `RESOLUTION`；含 `+` 行 → `SMUGGLED`；只含 `-` 行 → `DROPPED` 候选。
"删除一段内容"属于 **DROPPED**（静默吞掉），不是 SMUGGLED——按"哪个 diff 命令产生的"分类
会把同一处改动同时报成两类。

首期 **11 个** = 题面要求的 10 个（夹带 4 / 吞掉 3 / 正确解冲突 2 / octopus 1）
+ 1 个反例守护（`drop-then-readd`：重引入抑制）。实测计数由生成器在**生成期**与声明对账
（`_validate_declared`），不符即失败。

| # | 名称 | 注入 | 声明期望（实测一致） |
|---|---|---|---|
| f01 | `smuggle-extra-line` | 解冲突后在无关函数里多写一行 | `smuggled=1`, `dropped=0` |
| f02 | `smuggle-unrelated-file` | 夹带一个与冲突无关的文件的修改 | `smuggled=1`, `dropped=0` |
| f03 | `smuggle-function-body` | 冲突区外把函数体改掉（倍率 2→3） | `smuggled=1`, `dropped=0` |
| f04 | `smuggle-new-file` | 解冲突时新增一个两侧都不存在的文件 | `smuggled=1`, `dropped=0` |
| f05 | `drop-guard-check` | 解冲突时删掉 `guard()` 的负数校验（= 吞掉） | `smuggled=0`, `dropped=1` |
| f06 | `drop-one-side` | 整段丢掉一侧新增的函数 | `smuggled=0`, `dropped=1` |
| f07 | `drop-partial-hunk` | 只保留一侧新增函数的一部分 | `smuggled=0`, `dropped=1` |
| f08 | `clean-resolution-a` | 正确解冲突（两侧改动各占一行） | `smuggled=0`, `dropped=0`, `resolution>=1` |
| f09 | `clean-resolution-b` | 正确解冲突（语义合并成一行） | 同上 |
| f10 | `octopus` | 三父 octopus merge | `skipped=[{reason:"octopus"}]`，不进 `blob_fidelity` 分母 |
| x01 | `drop-then-readd` | 丢掉的 hunk 被**后续提交原样补回** | `smuggled=0`, `dropped=0`（反例） |

**M2 待补（已记入 `plan/HANDOFF-M2.md`）**：`custom-driver` fixture（`.gitattributes` 指定自定义
merge driver）→ `skipped=[{reason:"custom_driver"}]`。首期未纳入 M1 的原因是需要一个
跨平台可用的 driver 命令，留到实现 `SKIPPED(custom_driver)` 判定时一并落地（判定与 fixture 同步做）。

### 3.1 `expect.json` 结构

```json
{
  "fixture": "smuggle-extra-line",
  "suite": "fidelity",
  "injects": ["SMUGGLED"],
  "generator_version": "1",
  "commits": {"head": "<oid>", "branches": {"main": "<oid>", "feature/synth-a": "<oid>"}},
  "expect": {
    "exit_code": 0,
    "merges": [{"merge_oid":"<oid>","blob_fidelity":0.8,"counts":{"smuggled":1,"dropped":0,"resolution":0},
                "hunks":[{"kind":"SMUGGLED","path":"src/synthapp/x.py","old_range":"-","new_range":"4,1"}]}],
    "skipped": []
  }
}
```

**真值纪律**：`expect.json` 只存**期望**，不存观测；期望值可由生成器输入的注入清单独立推导（生成器内部有 `EXPECTED = ...` 常量，与 `fidelity` 实现零共享）。

## 四、parity fixture 集

**apply 兜底挂在 A（源侧）**，patch-id 用 `-U0`、apply 检查用 `-U3`（口径见 `data/README.md` §4.4）。

| 名称 | 构造 | 期望（实测） |
|---|---|---|
| `bidirectional-basic` | `release/1.0` 的 2 个修复 vs `main` 的 3 个改动 | 双向三态齐：`PRESENT(basis=patchid)` / `MODIFIED` / `MISSING` |
| `context-shift` | 同一改动落在第 2 行 vs 第 6 行、上下文不同 | 双向均 `PRESENT(basis=patchid)` |
| `whitespace` | `value=1` vs `value =    1`，上下文不同 | 双向均 `PRESENT(basis=patchid)` |
| `partial-apply` | A 侧改动了候选补丁的**上下文行** | 双向均 `MODIFIED` |
| `true-missing` | 目标侧完全没有 | `MISSING` |
| `path-remap` | 同内容换到另一个路径 | `MISSING` + `note=content_equivalent_at_other_path` |

> `path-remap` 的期望在 M1 由**定义**推出：路径参与 patch-id，apply 也按路径匹配，
> 所以"别处有同内容"不构成 PRESENT。原先设想的 `PRESENT(note=path_remapped)` 被实测推翻，
> 已按定义修正（原设想的唯一变动点是 `plan/04` 这一行与 `plan/03` §2.2）。

`expect.json` 里登记每个 commit 的 `u0_patchid`（由生成器用**独立实现**算一遍：
`git diff-tree -p -U0` | `git patch-id --stable`，复用 `parity.py` 的实现不算数）。

## 五、ledger fixture 集

| 名称 | 构造 | 期望 |
|---|---|---|
| `no-successor` | revert 一个修复，之后不再重做 | `REVERTED_NO_SUCCESSOR` |

## 六、golden 与测试的关系

- golden 文件（`expect.json`）是**数据资产**，测试读它并断言"实现输出 == golden"。
- **`--check` 守门两层**：① 冻结 golden 自身形态合法（JSON 可解析、必填键齐、无 `observed_*`）；② 重跑生成器到临时目录 → OID 与 golden 逐项一致。
- **反例必须存在**：f08/f09 断言"不报 SMUGGLED/DROPPED"，防止"见 merge 就报"骗过验收。
- **变异验证**：手工把 f01 的注入删掉 → 测试必须红（否则 golden 是假门）。

## 九、M1 实测：生成器确定性证据（2026-10-18）

| 项 | 实测 |
|---|---|
| 生成器 | `tools/gen_fixtures.py`（零依赖，不 import `mergefidelity`） |
| 套件规模 | fidelity 11 · parity 6 · ledger 3 = **20** |
| 位级一致 | `py -3.8 tools/gen_fixtures.py --out data/fixtures --check` → `--check 通过：20 个 fixture 与冻结产物逐字节一致`（exit 0）；`tests/test_gen_fixtures.py::test_check_regenerates_byte_identical_from_frozen`（`slow`）复证 |
| 生成期自证 | 每个 fidelity fixture 的**声明计数**（`declared_counts`）与实际 oracle 复算逐项对账，不符即 `GenError`（`_validate_declared`） |
| 反例 | `clean-resolution-a/b`、`drop-then-readd` 三个反例断言 `smuggled=0 且 dropped=0` |
| 仓库本体 | 生成到 `data/fixtures/<suite>/<name>/repo/`，被 `.gitignore` 排除；入仓的是生成器 + `expect.json` + 每例 `README.md` + `manifest.json` |

### M1 实现中踩到的三个坑（都写进了代码注释与 oracle）

1. **`merge-tree --write-tree` 的对象落点**：必须用 `GIT_OBJECT_DIRECTORY` + `GIT_ALTERNATE_OBJECT_DIRECTORIES`
   隔离，且**目标对象目录要预先存在**（否则 git 报 `fatal: not a git repository`）；
   oracle 必须在**同一对象环境**里读机械树（`ls-tree` / `diff`），否则临时目录一删就读不到树。
2. **`git diff-tree ... -- <path>` 的参数顺序**：`--` 必须排在 revisions **之后**，否则 git 直接报用法错误（exit 129）。
3. **根提交没有父提交**：`<c>^` 对根提交会 `unknown revision`；patch-id 复算要走 `--root`（取反无意义，返回 `None`）。
